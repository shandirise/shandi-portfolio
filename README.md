# Shandi Himawan — Portfolio

Personal portfolio of **Shandi Himawan**, fullstack developer from Purwokerto, Indonesia.
A fast, static site in **English and Indonesian**, built with [Astro](https://astro.build) from an editorial grid design made in Figma.

**Live:** [shandi-portfolio.vercel.app](https://shandi-portfolio.vercel.app) · [Bahasa Indonesia](https://shandi-portfolio.vercel.app/id/) · CV: [EN](https://shandi-portfolio.vercel.app/cv/Shandi-Himawan-CV-EN.pdf) / [ID](https://shandi-portfolio.vercel.app/cv/Shandi-Himawan-CV-ID.pdf)

## Highlights

- **Bilingual** — English at `/`, Bahasa Indonesia at `/id/`; switching language keeps your place on the page.
- **Content-driven** — every word, link and date lives in typed files in `src/data/`; no component edits needed to update the site.
- **CV generated from the same data** — the "Download CV" button serves an ATS-friendly PDF (EN + ID) built at deploy time, so the site and the CV never drift apart.
- **Self-maintaining details** — section numbers, navigation, counts, the Journey timeline and the "Used in…" lines under each skill are computed from the data.
- **Motion with restraint** — grid lines draw in, headings rise, numbers count up; all of it turns off for visitors who prefer reduced motion, and every word is readable without JavaScript.
- **Static and light** — no client framework, a single small script, self-hosted fonts.

## Getting started

Requires Node 22 or newer.

```bash
npm install
npm run dev        # http://localhost:4321 — updates as you save
npm run build      # production build in dist/
npm run preview    # serve the production build locally
npm run check      # type-check content and components
```

## Editing content — `src/data/`

| File | What's in it |
| --- | --- |
| `profile.ts` | Name, email, LinkedIn/GitHub, timezone, SEO text |
| `sections.ts` | Order of sections, nav labels, headings — `enabled: false` hides one |
| `hero.ts` | Latest-work card, intro, the four stats |
| `featured.ts` | The two big case studies |
| `experience.ts` | Roles and "Other roles" |
| `research.ts` | The journal article, key findings, abstract, DOI |
| `projects.ts` | The "Other projects" table |
| `skills.ts` | Skill groups, core stack, soft skills |
| `certificates.ts` | Certificates |
| `journey.ts` | The timeline with real dates — also the source of the CV's experience and organisations |
| `about.ts`, `gallery.ts`, `contact.ts` | About text, photos, closing band |
| `cv.ts` | Things only the PDF CV needs (longer summary, languages, headings) |
| `ui.ts` | Small interface words (buttons, labels) |

Text is either the same in both languages or translated:

```ts
title: 'Fundor.hu',                                                  // same in EN and ID
oneLiner: { en: 'Grant-matching platform…', id: 'Platform pencocokan hibah…' },
```

Computed for you:

- Section numbers (01, 02…), the top nav and the hero "Contents" list follow `sections.ts`.
- Counts in headings ("Six more projects", "27 entries") use `{count}` / `{CountWord}`.
- Each skill's "Used in…" line comes from the projects whose `stack` lists it.
- Journey year groups, filter chips, counts and "+3 more" previews come from `journey.ts`.

## The PDF CV

- Served at `/cv/Shandi-Himawan-CV-EN.pdf` and `/cv/Shandi-Himawan-CV-ID.pdf`; each language page links its own.
- Built on every deploy; generated fresh on each download during `npm run dev`.
- `cv: 'full' | 'brief' | false` on a journey entry or project sets how much the CV shows (the website always shows everything). The build warns if it grows past two pages.
- ATS-friendly on purpose: one column, selectable text, standard headings, no photo, no phone number.
- Generator: `src/lib/cv.ts`.

## Images and files — `public/`

| File | Appears as |
| --- | --- |
| `images/shandi-himawan.png` | About photo |
| `images/gallery/*.jpg` | Gallery (listed in `gallery.ts`) |
| `files/bnsp-programmer-shandi-himawan.pdf` + `images/certificates/*.jpg` | Certificate link and thumbnail |
| any image + `cover.image` in `featured.ts` | Case-study screenshot (optional) |

An empty link (`''`) or a missing file shows as a **dashed orange outline** during `npm run dev` and is **left out** of the production build, so the live site never shows a broken link. The Gallery stays hidden until it has at least one photo.

## Design and motion

- **Colours, fonts, spacing, animation speed:** `src/styles/tokens.css`
- **Shared styles and the reveal system:** `src/styles/global.css`
- **Scroll behaviour:** `src/scripts/motion.ts`
- **One section's layout:** `src/components/sections/<Name>.astro`

## Deployment

Deployed on Vercel from this repository: every push to `main` goes live. Vercel detects Astro automatically (build `npm run build`, output `dist`).

The site address used for canonical links, language alternates and the CV header is read from Vercel's `VERCEL_PROJECT_PRODUCTION_URL`. For a custom domain, set a `SITE_URL` environment variable (e.g. `https://shandihimawan.com`) in the Vercel project.
